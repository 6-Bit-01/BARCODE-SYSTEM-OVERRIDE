## How discoveries will be implemented

1. Reserve stable IDs and keep lore, Easter eggs, mandatory keys and optional modules distinct. The existing progress.easterEggs field is an envelope, not a finished discovery service.
2. Trigger from an actual authored inspection, location or event. Drawing, pausing, resizing or reading the archive cannot grant discoveries.
3. Save once, tolerate revisits/reload/blocked storage, and allow appropriate repeat viewing without duplicate rewards. Extend the current canonical save rather than creating an unrelated slot.
4. Keep hints in-world and optional. Never advertise the secret ending test, invent a percentage threshold, or require a reference joke to understand or finish the story.
5. Comms/panel events use current input/lifecycle owners; captions and cues remain readable, skippable where appropriate and compatible with reduced flashes/shake. Gameplay and music cannot secretly desynchronize for a gag.
6. Track setup, return scene, payoff, asset IDs, text status and credits. Produce exact text only after the scene's role is clear.
