## Integration

The game already has one gameplay animation loop. The Level 2 branch calls RoadProof update and draw directly; replacing the generic Renderer alone would not change Level 2. The new component is called from this existing owner and does not create an Application, ticker, input system or audio system.

The main display Canvas retains its 2D context and draws the functional road cues, vehicles, dashboard, mirror face and glass markings. Scenery renders directly into a visible GPU layer underneath that transparent foreground. Both layers fit the same complete native 1920×1080 frame. There are no per-frame GPU-to-native copies. The existing pause screenshot composites both layers once, then hides the GPU layer while its opaque paused image is displayed.

`cache-road-gpu-context.js` records the existing scenery projection as image/triangle/path/gradient commands. `cache-road-gpu-renderer.js` retains source textures and GPU object pools between frames. The facade also retains the original Canvas operations for complete same-frame replay when GPU rendering is unavailable or cannot complete.

Adjacent commands share immutable clip chains. The final simple convex triangle or quad clip on an image becomes textured mesh geometry with interpolated UVs and pooled buffers, instead of a separate stencil pass. Curved, compound and earlier clips remain. Moving parking signs reuse one canonical high-resolution glyph with geometric scaling and tint; changing their apparent size never creates another font texture.

Simple convex gradient fills likewise use their exact projected vertices without a stencil; curves, compound paths and strokes retain their masks. All 171 Level 2 GPU sources are prepared and uploaded before the level's control/audio handoff; both views retain them throughout play. Successful compressed sources transcode before any explicit original-image decode. Gameplay performs no new source uploads. The existing bounded preparation path remains for context recovery or unexpected demands; promise callbacks never upload or schedule gameplay. Loader waits include the existing bundled fallback and valid original-image readiness. Optional native SVG bitmaps prepare in the background without holding either the GPU or original native fallback hostage; GPU warmup owns each required original decode once. Dispose cancels the handoff immediately without waiting for late source completion.

Forward scenery is queued during the existing draw and presented once at its end. The rear scene uses bounded 714×141 targets and one separable Gaussian blur at the original 2.3-pixel radius, clipped by the recorded original mirror outline. Cache's face and glass markings remain native and sharp. The blur samples the glass backdrop in its padded target; this deliberately does not reproduce the former Canvas self-copy's accidental sampling of neighboring HUD pixels. Initialization, unsupported hardware, context loss or a failed final presentation use a complete same-frame original native draw; partial or stale GPU frames are hidden.

During the authored opening, the HUD fades through its existing context proxy. Cinematics registers that proxy in a WeakMap so Road validates the underlying frame owner while retaining logical alpha for recording and fallback replay. Both scenery views stay on the GPU during the fade. The rear target paints its original full-strength scene; the final vertical Gaussian applies the HUD opacity once to premultiplied RGBA. Native face/text retain their existing fade. Failed direct rear capture invalidates the whole frame and uses the same complete native recovery, rather than mixing forward GPU output with a native rear self-copy.

Original atlas cells and source crops are represented with UVs, not new image decodes or downsampled artwork. The moving road and banks cannot be cached as one scrolling screenshot: their nonlinear projection changes with progress, terrain and camera. Their original geometry is projected each frame while their images remain resident on the GPU.

## Resource ownership

PixiJS 8.22.0 is bundled locally with its exact MIT license and integrity receipt. The adopted texture pipeline generates full-resolution legacy UASTC KTX2 derivatives offline for the 149 raster images, with complete mip chains, extruded edge padding and premultiplied UNORM RGBA. The 22 small SVG sources keep original browser rasterization as ordinary GPU image textures; their full mip allocation totals about 4.818 MiB. All 171 sources remain required. All canonical original artwork remains unchanged for native rendering and fallback. These compressed derivatives are lossy at high quality, not a lossless artwork rewrite or a resolution reduction.

A single level-owned worker uses the exact local Basis Universal 2.50 decoder, Apache-2.0 license and Git-blob provenance to transcode the derivatives into a supported hardware texture format before driving. Direct Pixi compressed sources avoid its optional CDN loaders and global Assets cache. Native KTX handles release after each source; transferred mip arrays remain only for the level's graphics recovery, and the worker/WASM heap terminates after warmup. Unsupported hardware or a failed derivative uses the preserved original image. Playing frames do not transcode, decode or upload new artwork. Original source dimensions/crops remain separate from four-pixel storage padding.

Both Pixi tickers have automatic startup disabled. The GPU surface has no native event target and cannot intercept input. Texture eviction is explicit and bounded; cleanup runs through the existing update owner. There is no Pixi Application or second gameplay animation loop.

The GPU background uses the engine's recommended opaque, non-MSAA settings; the native foreground remains transparent. Cutout textures retain premultiplied alpha, linear sampling and full mipmaps. Native resolution is unchanged. Explicit GPU cleanup runs during guarded level preparation, rather than interrupting an active frame. The one-sample main target and two 714×141 rear targets total 2,274,948 texels.

The existing native ImageBitmap cache retains its 32-million-pixel cap. The GPU texture pool has a distinct explicit 256 × 1024²-texel budget, including mip chains and rendering targets, equivalent to at most 1 GiB of RGBA storage. That is a renderer allocation bound, not a claim about total browser memory. Decoded original Images, the legacy fallback cache and driver overhead are separate. Only the Level 2 GPU source set is uploaded, excluding other levels, native-only HUD artwork and unrelated assets.

The standalone loader starts with the 28 Level 1 originals rather than the entire 256-source catalog. The road handoff selects all 171 GPU originals plus 26 native vehicle/HUD/cue originals, waits for all of them, and releases out-of-scope images and derivatives. This 197-source primary set is 835.55 MiB in base RGBA equivalents, versus 1,108.37 MiB for the catalog. The 22 additional planted pedestrian fallback sources (132.12 MiB) load only when their corresponding original animation exhausts the existing source attempts. GPU-only images retain the original native fallback source while suppressing unused native bitmap duplicates. These inventories describe potential allocations; they do not measure OS reclamation.

Standalone sprite suspension releases each Level 1 atlas source even when inactive clones still retain their sheets. Return/new Level 1 play explicitly await original PA artwork and reload/rebind sprites before their existing runtime reset and music handoff. Their pending resource waits are cancellable through the existing lifecycle cleanup registry. Prepared road entry also retires inactive Level 1 parallax/video, cutscene and traffic originals and exact Level 1 profile audio buffers/promise references; title, campaign/save and road audio owners remain. The helper reports pending original-owner jobs instead of claiming that uncompleted work was reclaimed. At Road disposal, GPU textures and all image/decode/demand maps release before PA image sources; the small reusable surface and object pools remain. Fifty-one GPU contracts, ten PA scene contracts, decoded-atlas reload pixels and production owner/profile checks cover this lifetime change. Browser acceptance is separate.

A header-only inventory of the actual production key set finds 255,565,094 source mip texels for all 171 originals, before explicit rendering targets and the canonical parking glyph. The portable production checker asserts their complete total stays within 268,435,456 texels, and repeated resident updates perform no further uploads or decodes. These are allocation inventories, not measured physical memory.

The completed derivative bank has 149 compressed raster sources and 22 original SVGs. Source mip storage changes from 1,022,260,376 bytes (974.903 MiB) in uncompressed RGBA to 260,390,544 bytes (248.328 MiB): 255,338,784 compressed block bytes plus 5,051,760 original SVG RGBA mip bytes. Render targets/glyphs and driver overhead are separate. Lossless Zstd reduces the KTX2 files to about 122.274 MiB on disk. Every raster derivative passed the exact shipped Basis decoder's all-mip BC7 transcode check, and all 171 original hashes remained unchanged. These are verified encoded allocations; physical runtime memory and pacing still require the actual built-game result.
